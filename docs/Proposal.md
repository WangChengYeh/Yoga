# YogaFlow 3D
## 視覺化智慧：重新定義居家瑜珈

> 數據自主 • 即時引導 • 個性化成長

---

## 1. 打破反饋黑箱

**為什麼 90% 的居家練習者無法持續進步？因為他們看不見自己的錯誤。**

### 影片練習的侷限
傳統瑜珈影片只有單向輸出，練習者無法得知自己的脊椎是否過度彎曲，或關節角度是否安全。

### 昂貴的私教成本
高品質的私人教練每小時收費昂貴且需配合預約，難以滿足隨時隨地練習的需求。

### 核心痛點：自學者的視覺盲區

---

## 2. 視覺化關節引導

**「看見」看不見的角度**

系統自動計算教練影片中的「標準角度」與使用者「當前角度」的毫秒級差異。

- **紅區警示**：當關節偏離超過閾值
- **動態引導**：箭頭指示動作修正方向
- **實時疊加**：3D 骨架與影像合一

---

## 3. 個性化身體基線追蹤

| 功能 | 說明 |
|------|------|
| **活動度評估** | 記錄每個關節的極限 ROM (Range of Motion)，為每位使用者建立獨特的身體檔案 |
| **疲勞感知** | 分析動作穩定度，判斷肌肉疲勞程度，適時建議休息以預防受傷 |
| **平衡分析** | 透過重心追蹤與雙側角度對比，優化身體對稱性與核心穩定 |

## 4. 目標差距動態分析

> 「目前您的關節活動度已提升 25%，距離目標英雄三式尚有 12 度的傾斜優化空間。」

**進步路徑可視化：邁向大師級標準**

系統不僅顯示「不對」，更分析你與「目標」的距離，將練習變成有趣的升級過程。

---

## 5. 技術核心：Edge-AI 視覺引擎

利用 MediaPipe 實現高效能 3D 骨架抽取與 33 個關鍵點追蹤，確保側向、倒立等複雜姿勢依然穩定。

### 系統架構

```
CameraX (影像輸入)
    ↓
MediaPipe Pose (33 關鍵點 3D 骨架)
    ↓
Pose-aware State Machine (姿勢判斷)
    ↓
Flow Engine (時序控制)
    ↓
Gemma LLM on-device (語言層)
    ↓
TTS + 3D Avatar Coach (輸出)
```

## 8. 居家練習展示場景

**場景：低光源臥室中的單人居家瑜珈練習**

在家中臥室環境，單一使用者穿著貼身運動服裝，在床邊進行瑜珈練習。房間採用紅色氛圍燈與紅外線感測輔助，在低光源條件下依然能維持姿態辨識穩定度。

床邊放置手機與網紅常用手機架，手機鏡頭對準練習者全身。YogaFlow 3D 透過前鏡頭或外接視角捕捉單一使用者的身體關鍵點，在畫面上疊加 3D 骨架、關節角度與修正箭頭，並由 AI 教練即時指導瑜珈姿勢。

### 展示重點

- **低光源可用性**：紅色燈光與紅外線輔助下仍可進行姿勢追蹤
- **真實居家場景**：床邊、手機、手機架即可完成互動練習
- **單人姿態追蹤**：系統鎖定主要練習者，避免背景人物或環境物件干擾判斷
- **AI 即時指導**：語音提示調整手臂、髖部、膝蓋與脊椎角度
- **隱私優先**：臥室影像只在本機分析，不上傳雲端

## 9. 盈利模式

**免費完整功能 + 個性化加值服務**

YogaFlow 3D 的核心 App 採免費模式，讓使用者不付費也能使用完整的姿勢偵測、即時語音指導、3D 骨架疊加與基本練習流程。商業模式不以限制核心功能為主，而是透過個人化、內容擴充與生態合作創造收入。

### 收入來源

| 模式 | 說明 |
|------|------|
| **客製化瑜珈流程** | 使用者可付費建立個人化訓練流程，例如肩頸放鬆、髖關節開展、睡前伸展、復健導向流程或特定體式進階計畫 |
| **輔具推薦合作** | 根據使用者姿勢需求推薦瑜珈墊、瑜珈磚、伸展帶、手機架、紅外線補光設備等輔具，並向合作廠商收取推薦、導購或曝光費用 |
| **3D 教練 Skin** | 基本 AI 教練免費；不同風格的 3D 健身教練外觀、聲線、服裝與互動風格可作為付費 skin 或主題包 |
| **品牌聯名內容** | 與健身教練、瑜珈老師、網紅或運動品牌合作推出聯名流程與專屬教練角色 |

### 原則

- **核心功能免費完整**：姿勢偵測、角度提示、基礎流程與隱私保護不設付費牆
- **付費買的是個性化與體驗**：不是為了移除限制，而是取得更貼近個人目標的流程與教練形象
- **推薦透明化**：輔具推薦需標示合作或贊助關係，避免破壞使用者信任
- **不販售使用者影像資料**：商業化不建立在上傳、販售或分析私人影像資料之上

## 12. Agentic AI 開發流程

本專案採用 PM、RD、AE 三角色的 Agentic AI 協作模式，讓產品規格、核心技術與應用落地可以並行推進。

| 角色 | 定位 | 主要職責 | 產出 |
|------|------|----------|------|
| **PM（Product Manager）** | 規格與需求負責人 | 定義使用者場景、產品需求、商業模式、功能優先級與驗收標準 | PRD、User Story、Issue、驗收條件 |
| **RD（Research & Development）** | 核心技術實作者 | 實作姿勢偵測、3D 骨架、角度計算、Flow Engine、on-device AI 與效能優化 | 核心模組、演算法、SDK、測試報告 |
| **AE（Application Engineer）** | 應用整合與體驗落地 | 將 RD 核心能力整合到 App，完成 UI/UX、教練互動、場景流程、輔具推薦與商業化功能 | App 功能、Demo、整合文件、使用流程 |

### 協作節奏

```
PM 定規格與驗收標準
    ↓
RD 開發核心能力與技術模組
    ↓
AE 整合成可用 App 與展示場景
    ↓
PM 驗收體驗、重新排序需求
```

### Agentic AI 分工

- **PM Agent**：整理需求、拆解 GitHub Issues、維護 roadmap、確認每個功能的使用者價值與驗收標準
- **RD Agent**：修改核心程式碼、建立測試、處理 MediaPipe / CameraX / 3D 骨架 / LLM on-device 等技術問題
- **AE Agent**：負責 App 端串接、Demo 場景、提示詞文案、教練互動流程與商業化功能整合

指令頻道：GitHub Issues 作為任務來源，Pull Request 作為交付與審查節點。
